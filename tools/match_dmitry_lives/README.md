# match_dmitry_lives — свързване на томовете с дневния изглед

## Какво е това

Дванайсетте тома „Жития на светиите“ по свт. Димитрий Ростовски съдържат 1155
четива. Този конвейер намира **кой светия от календара на кое четиво
отговаря** и записва връзката, за да се появи ред „Сказание по Димитрий
Ростовски“ под светията в дневния изглед.

⚠ Работата е **вече свършена** (1150 връзки в `lives.saint_dmitry_refs`).
Папката се пази заради приемствеността — ако томовете се пресглобят или се
добавят светии, редът е този.

## Пълният ред

```bash
cd tools/match_dmitry_lives/scripts

python3 01_extract_dmitry.py        # томовете → четивата (дата, заглавие, номер)
python3 02_extract_saints.py        # семето → светиите
python3 03_match.py                 # засечка ПО ДЕН
python3 03b_find_saints_duplicates.py   # проверка за дублирани редове
python3 04_build_dmitry_refs.py     # → lives.saint_dmitry_refs
python3 05_add_new_saints.py        # добавя липсващите светии в семето
python3 06_hymns.py                 # песнопенията от томовете → lives.hymns
```

Всички приемат `--dry-run`; `06_hymns.py` и `--verbose`.

```bash
python3 04_build_dmitry_refs.py --dry-run
python3 06_hymns.py --dry-run --verbose
```

Дванайсетте `build_<месец>_review.py` са **еднократни** — с тях е правен
ръчният преглед месец по месец. Не са част от редовния ред.

## ⚠ Предупреждения

- ⚠⚠ **КЛЮЧЪТ Е `slug`, НЕ `saints.id`.** Идентификаторът е `AUTOINCREMENT` и
  се преномерира при всяко пускане на `merge_years.py`, а в многогодишна база
  един светия има **по един ред на година**. Слъгът е стабилен — и пътьом
  решава случая с един светия на две законни дати (Мария Египетска).
- ⚠⚠ **ДАТАТА В СЕМЕТО Е ГРАЖДАНСКА, не църковна** (църковна = гражданска − 13
  при стар стил). Без това превръщане сравнението е „ябълки срещу круши“
  (`01-14` срещу `01-01`), дава 0% съвпадения **без нито една грешка** и
  изглежда, че скриптът е счупен.
- ⚠ **Засичането е ГРУПИРАНО ПО ДЕН**, не глобален праг: сравняват се само
  кандидати от същия ден.
- ⚠ **Томът за юни пише „юний“**, не „юни“ — архаично. Иначе целият месец
  мълчаливо отпада.
- ⚠ **`06_hymns.py` пипа САМО празните слъгове.** Слъг с песнопения от
  azbyka.ru не се докосва — те са по-пълни, а добавянето отгоре дава
  **дублиране** в секцията.
- ⚠⚠ **РЕДЪТ СПРЯМО azbyka: първо `16_build_hymns_table.py`, после
  `06_hymns.py`.** Първият прави `DROP TABLE` и сглобява наново; пуснат след
  втория, изтрива неговите редове.
- **Резервното копие ляга в `backups/`, НЕ до базата** — `pubspec.yaml` включва
  цялата `assets/db/`, тъй че `lives.db.bak-…` там пътува в APK-то.
